# 텍스트 제거 로직 비교 분석 보고서

## 1. 개요

본 보고서는 `make_slide` 프로젝트에서 워터마크 및 텍스트 제거 시 발생하는 "지운 흔적(Inpainting Artifacts)" 문제를 해결하기 위해, 3가지 기술 시나리오를 비교 분석한 결과입니다.

**목표**: 배경이 복잡한 이미지(NotebookLM 슬라이드 등)에서도 흔적 없이 깔끔하게 텍스트를 제거하는 최적의 방안 도출.

## 2. 비교 대상 시나리오

1.  **Scenario A (로컬 오픈소스 조합)**
    - **감지(Detection)**: `EasyOCR` (오픈소스 OCR 모델)
    - **복원(Inpainting)**: `OpenCV Telea` (전통적인 알고리즘)
    - **특징**: 완전 무료, 로컬 구동 가능, 낮은 하드웨어 요구사양.

2.  **Scenario B (딥러닝 Inpainting 도입)**
    - **감지(Detection)**: `EasyOCR` (오픈소스 OCR 모델)
    - **복원(Inpainting)**: `LaMa` (Large Mask Inpainting, 딥러닝 생성 모델)
    - **특징**: 상용 서비스급 복원 품질, GPU 서버 필수.

3.  **Current: make_slide (현재 구현 방식)**
    - **감지(Detection)**: `Google Gemini 3.0 Flash` (최신 멀티모달 AI)
    - **복원(Inpainting)**: `OpenCV Telea` (전통적인 알고리즘)
    - **특징**: 최상의 감지 능력, 그러나 복원 품질은 낮음.

## 3. 상세 비교 분석

### 3.1 감지(Detection) 정확도

텍스트를 얼마나 정밀하게 찾아내는가?

- **Current (`Gemini 3`)**: **[최상]**
  - 단순 글자 인식뿐만 아니라 "이것이 지워야 할 레이아웃 요소인가?"를 문맥적으로 이해합니다.
  - 기울어진 글자, 디자인된 폰트, 겹친 글자도 정확히 잡아냅니다.
- **Scenario A & B (`EasyOCR`)**: **[중]**
  - 일반적인 가로쓰기 텍스트는 잘 찾지만, 복잡한 디자인이나 배경색과 비슷한 글자는 놓칠 수 있습니다.
  - 오인식(글자가 아닌데 글자로 인식)이나 미인식(글자를 못 찾음) 비율이 Gemini보다 높습니다.

### 3.2 복원(Inpainting) 품질 (핵심 이슈)

지운 자리를 얼마나 감쪽같이 메꾸는가?

- **Scenario B (`LaMa`)**: **[최상 - Unwatermark.ai 급]**
  - 배경의 패턴을 이해하고 "그려넣는" 방식입니다.
  - 복잡한 그라데이션, 사진 배경 위에서도 흔적이 거의 남지 않습니다.
- **Current & Scenario A (`OpenCV`)**: **[하 - 흔적 남음]**
  - 주변 픽셀 색을 안쪽으로 번지게 하는 방식입니다.
  - 단색 배경은 완벽하지만, **복잡한 배경에서는 뿌옇게 뭉개진 자국(Blur)이 선명하게 남습니다.**
  - 사용자가 현재 불만을 느끼는 근본 원인입니다.

### 3.3 비용 및 인프라

- **Scenario A**: 무료, CPU 구동 가능.
- **Current**: API 비용 발생(매우 저렴), CPU 구동 가능.
- **Scenario B**: **GPU 서버 필수**. (클라우드 GPU 임대 시 시간당 비용 발생 또는 고사양 로컬 PC 필요).

## 4. 종합 비교표

| 구분              |   **Scenario A**    |       **Scenario B**        |   **Current (make_slide)**   |
| :---------------- | :-----------------: | :-------------------------: | :--------------------------: |
| **구성**          |  EasyOCR + OpenCV   |       EasyOCR + LaMa        |    **Gemini 3 + OpenCV**     |
| **감지 성능**     |       ⚠️ 보통       |           ⚠️ 보통           |   **🏆 최상 (AI Vision)**    |
| **복원 품질**     | ❌ 낮음 (흔적 남음) | **🏆 최상 (Unwatermark급)** |     ❌ 낮음 (흔적 남음)      |
| **처리 속도**     |   빠름 (1초 내외)   |  느림 (GPU 없으면 수십초)   | **매우 빠름 (API+알고리즘)** |

| **사용자 만족도** |        낮음         |            높음             |       보통 (지저분함)        |

## 5. 결론 및 제언

사용자가 겪고 있는 **"지운 흔적이 많이 남는다"**는 문제는 **OpenCV Inpainting 알고리즘의 한계** 때문입니다. 감지 로직(Gemini vs EasyOCR)과는 무관합니다.

따라서 가장 이상적인 해결책은 **시나리오 B의 복원 기술을 현재 방식에 이식하는 "Hybrid 모델"**입니다.

### ✅ 추천 솔루션: Hybrid (Gemini 3 + LaMa)

- **감지**: 현재의 압도적인 **`Gemini 3 Flash`** 유지. (EasyOCR로 다운그레이드할 이유 없음)
- **복원**: `OpenCV`를 버리고 **`LaMa` (AI Inpainting)** 도입.

**실행 전략**:

1.  **단기 (PoC)**: `LaMa` 모델의 Onnx(경량화) 버전을 로컬 CPU 환경에서 테스트해봅니다. (속도는 느리지만 품질 검증 가능)
2.  **적용**: `make_slide`의 `image_processor.py`에서 `cv2.inpaint` 함수를 `LaMa` 추론 코드로 교체합니다.

이 방식만이 **"완벽한 감지"와 "완벽한 제거"**를 모두 달성할 수 있는 유일한 길입니다.
